# Starter content

A fresh knowledge base starts with working content, not a blank page — so
a client's day one begins with decisions to react to instead of a cursor
to stare at.

The starter content ships with the knowledge base's authoring kit:

- **Accepted engineering decisions** — trunk-based development, ADR
  governance, dependency auditing, automated testing, and a shared
  glossary — several carrying stored implementation plans, so a fresh
  space is [Adopt](./loop/adopt.md)-ready from the first hour.
- **A proposed backlog** — CI, code review, refactoring, monitoring,
  incident management, feature flags, secrets handling, and more: a
  decision pipeline with ideas already in it.
- **A glossary and the ADR review-process guide** — the decision
  lifecycle's vocabulary defined once, and the governance mechanics
  written down as daily practice.

Nothing in it assumes a vendor, cloud, language, or CI system — every
concrete tool named is an example slot, not a prescription. And the
starter decisions are examples your team keeps, supersedes, or replaces:
superseding a starter opinion *is* the process working.

The content itself, and the one-command bootstrap that stands it up, live
with the kit in the
[llm-wiki repo](https://github.com/como-technologies/llm-wiki).
