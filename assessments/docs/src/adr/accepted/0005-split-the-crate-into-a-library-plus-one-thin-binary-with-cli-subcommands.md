# ADR-0005: Split the crate into a library plus one thin binary with CLI subcommands

> State: Accepted

## Status

Accepted

## Stakeholders

Como Technologies engineering — the assessments maintainers own this decision;
adroit's contract test pins the golden export this CLI produces, so the
Prescribe-stage tooling depends on the surface staying stable.

## Context and Problem Statement

assessments was a bin-only crate: `cargo test --lib` (the `just unit` recipe)
failed with "no library targets found", integration tests had no library to
link against, and the only way to get an export out of the app was the HTTP
route `GET /api/projects/{id}/export` — behind a server that, with the default
provider, cannot boot without `ANTHROPIC_API_KEY`. The Assess stage therefore
had no scripted end-to-end path, and the golden contract artifacts the
portfolio loop needs (schema.json plus a golden export for adroit to pin)
could not be generated by the real exporter. Something has to make the export
pipeline reachable from a shell without forking a second codepath that could
drift from the web app.

## Decision Drivers

- `just unit` / `cargo test --lib` must work — the house justfile contract
- Integration tests need to drive the real router and the real binary
- The export must be scriptable with no server and no API key in the
  environment (golden artifacts, CI, future dogfood recipes)
- One pipeline: a CLI export that could diverge from the HTTP export would
  make the committed golden meaningless as a contract for the HTTP surface
- The web app's behavior and configuration must not change

## Considered Options

- **Library + one thin binary with clap subcommands** — move every module
  into `src/lib.rs`; `src/main.rs` only parses the CLI and dispatches.
  Subcommands: `serve` (default, the existing web app), `export
  <project-id> --format yaml|json|toml --out FILE`, `validate <FILE>`,
  `schema --out FILE`. CLI and HTTP route share one
  `ExportService::export_project` function.
- **Separate `assessments-cli` binary or crate** — a second target reusing
  the services; keeps `main.rs` untouched but adds a second deployable,
  doubles the build surface, and still requires the lib split for tests.
- **Stay web-only, script via `curl`** — no code change, but exports would
  still require a bootable server (an API key with the default provider),
  CI could not pin a real-exporter golden, and `just unit` stays broken.

## Decision Outcome

Chosen: **library + one thin binary with clap subcommands**, because it fixes
the test-target gap and makes the export scriptable while guaranteeing —
structurally, not by convention — that the CLI and HTTP exports cannot drift:
both call `ExportService::export_project`, and an integration test asserts
byte-identity across all three formats. The headless subcommands never
construct an AI provider, so they run with no API key; `export` needs only
`DATA_DIR` (default `./data`), exactly like the web app's storage. `serve`
remains the default subcommand, so `cargo run` behaves as before.

### Positive Consequences

- `just unit` passes; integration tests link the library and drive the real
  router in-process (FakeProvider) and the real binary via `CARGO_BIN_EXE`
- The golden contract artifacts (`contract/schema.json`,
  `contract/golden-assessment.yaml`) are generated by the real exporter from
  a committed fixture, regenerable with `just golden` and pinned byte-for-byte
  in CI — adroit can pin the same file
- The Assess stage is scriptable end to end: seed → export → validate, no
  server, no key
- Schema generation became deterministic along the way (random UUID `default`s
  stripped), which a committed schema requires

### Negative Consequences

- Everything in the crate is now `pub` library API; internal refactors are
  visible to integration tests and any future external consumer, raising the
  cost of casual renames
- The provider `fake` module ships in the library (no longer `#[cfg(test)]`)
  so integration tests can build an `AppState` — a test double now lives in
  the production namespace, documented as test-only
- One more dependency (clap) and a second user-facing surface whose help text
  and flags must be kept in sync with the book's CLI page
- `serve`'s tracing/bootstrap moved from `main.rs` into `cli::serve`; anyone
  embedding the library must not assume `main.rs` holds setup logic

## Implementation

Landed with this decision: `src/lib.rs` declaring all modules,
`src/cli.rs` (clap `Cli`/`Command`, `run`, `export_cmd`/`validate_cmd`/
`schema_cmd`, `serve`), thin `src/main.rs`, shared
`ExportService::export_project`, `tests/golden_contract.rs` +
`tests/common/mod.rs` (deterministic fixture seeder), committed
`tests/fixtures/golden/` and `contract/` artifacts, and the `just golden`
regeneration recipe. The book's Command Line and Export Contract pages
document the surface and the artifact provenance.
